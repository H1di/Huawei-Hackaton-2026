# Признаки (features) — версия v1

**Автор:** Назар (Участник 2) · **Дата:** 26.10.2026 · **Код:** `features.py` · **Тесты:** `test_features.py`

## Файлы

Лежат в `data/features/` (в git не попадают, передаются через общий диск). Ключ везде `rowid`. Меток (`clicked`) в файлах **нет**: их берите из `fit.parquet` / `train.parquet` по `rowid`.

| Файл | Строки | История для статистик | Для чего |
|---|---|---|---|
| `fit_features.parquet` | события до 25.01 | `fit` (строка видит только более раннее) | обучение при проверке |
| `val_features.parquet` | первое событие каждого пользователя 25–27.01 | весь `fit` | проверка (AUC) |
| `train_features.parquet` | весь train | `train` (строка видит только более раннее) | обучение в финале |
| `eval_features.parquet` | evaluation | весь `train` | предсказание для сабмита |

## Главное правило против утечек

Все счётчики и CTR считаются через `asof.prior_stats`: строка видит только события **строго раньше** своего `timestamp`. Своя метка в признак никогда не попадает. Признаки из истории пользователя (`history_item_ids`, `history_timestamps`) утечек не дают, потому что история и так заканчивается до события.

## Список колонок

### Контекст и история пользователя

| Колонка | Что значит |
|---|---|
| `hist_len` | сколько кликов в истории пользователя (0–20) |
| `time_bucket` | шестичасовой блок суток (UTC), как в исходных данных |
| `day_type` | будни или выходной, как в исходных данных |
| `hour` | час события (0–23, UTC) |
| `secs_since_last_click` | секунд от последнего клика из истории до события (`null`, если история пустая) |

### Статистика товара (`item_id_*`) — «насколько товар популярен»

| Колонка | Что значит |
|---|---|
| `item_id_n_rows` | сколько раз товар показывали раньше |
| `item_id_n_clicks` | сколько раз на него кликнули |
| `item_id_n_events` | в скольких событиях он встречался |
| `item_id_n_click_events` | в скольких событиях на него кликнули |
| `item_id_ctr` | сглаженный CTR: `(клики + 20 * общий CTR) / (показы + 20)` |
| `item_id_secs_since_prev` | секунд с прошлого показа товара (`null`, если не показывали) |

### Статистика пользователя (`user_id_*`) — «как часто он кликает вообще»

Те же 6 колонок, но по пользователю: `user_id_n_rows`, `user_id_n_clicks`, `user_id_n_events`, `user_id_n_click_events`, `user_id_ctr`, `user_id_secs_since_prev`.

Важно для глобального AUC: активные пользователи кликают чаще, и модель должна это знать.

### Статистика пары «пользователь + товар» (`user_id_item_id_*`)

Те же 6 колонок, но для пары: показывали ли **этому** пользователю **этот** товар раньше и кликал ли он. Колонки: `user_id_item_id_n_rows`, `user_id_item_id_n_clicks`, `user_id_item_id_n_events`, `user_id_item_id_n_click_events`, `user_id_item_id_ctr`, `user_id_item_id_secs_since_prev`.

### Кандидат и история кликов

| Колонка | Что значит |
|---|---|
| `cand_in_hist_cnt` | сколько раз кандидат есть в истории кликов (0, если нет) |
| `cand_pos_from_end` | позиция последнего клика по кандидату с конца истории: 0 = самый свежий, 19 = самый старый (`null`, если кандидата нет в истории) |
| `cand_secs_since_click` | секунд с последнего клика по этому кандидату (`null`, если кандидата нет в истории) |

### Признаки внутри события (сравнение 10 кандидатов)

| Колонка | Что значит |
|---|---|
| `ctr_vs_event_mean` | `item_id_ctr` минус среднее `item_id_ctr` по 10 кандидатам события |
| `ctr_rank_in_event` | место кандидата по `item_id_ctr` среди 10 (1 = самый популярный) |
| `user_no_click_share` | доля событий пользователя без клика: `1 - n_click_events / n_events` |

## Про пропуски (`null`)

Пропуски оставлены намеренно: LightGBM и CatBoost умеют с ними работать. Они означают «такого события не было»: нет истории, товар не показывали раньше, кандидата нет в истории кликов. Не заполняйте их нулями, иначе «никогда не было» смешается с «было ноль секунд назад».

## Чего в v1 ещё нет (план на v2)

- тренд товара: клики за последние сутки и несколько часов;
- популярность товара в последние часы перед событием;
- идеи из EDA Участника 5 (например, как часто кликают товар, который уже есть в истории);
- скоры моделей Участника 4 (MF, item2vec, SASRec) подключаются отдельно через `rowid`.
